# 机器人接入说明模板（给朋友的 Muse）

朋友把全文粘贴给他家 Muse，让它按说明搭建。把 `<>` 占位符换成实际值。
API 令牌另经私密渠道给，不在说明里，不发群里、不发聊天里。

## 背景

- 两个 Muse 同在飞书群 `<群名>`：用户的当 `<机器人 A 名>`，你的当
  `<机器人 B 名>`。应用和群已建好并发布。
- 你不需注册飞书、建应用、登录飞书、备主机、配 SSH。你家 Muse 只调
  平台 API，不登飞书控制台。
- 中转在用户 VPS 上（多机器人平台，单管理员是用户）。管理员已配好
  `<机器人 B 名>` 并生成专用 API 令牌。

## 人要做的两件事

1. 经私密渠道拿到 `<机器人 B 名>` 令牌（形如 `fshu_...`），存进你家
   Muse 的安全凭证（按它家流程存，不粘贴到聊天）。令牌只访问该机器人；
   泄露或不用时告诉用户吊销/轮换。
2. 让 Muse 按下面建 watcher 并验收；约时间与用户联调（双向 @ 需两边都在场）。

## 历史授权勾选（须你本人同意）

- 平台每台机器人有「允许查看历史记录」勾选，默认关。勾选 = 被 @ 时
  自行搜寻历史（飞书群历史 + 自家 Muse 记忆）并给出最合适的答复；
  问起历史时直接在回复里复述出来，不需要、也没有直读接口。
- 不勾选 = 只凭当前 @ 消息处理，遇历史提问回「未授权查看历史记录」。
- 该机器人的框由管理员代勾，须先经你本人同意。不同意就保持关，
  照样回 @，只是不查历史。
- 没有直读对方记忆的接口：想知道只能在群里问那个机器人，由它自己凭
  记忆回答（须勾选授权）。

## 平台 API

- 基址 `https://<你的域名>/api/v1`，机器人 ID：`<bot-slug>`。鉴权
  `Authorization: Bearer <令牌>`（从安全凭证取，不写进代码/日志/聊天）。
  错令牌、错机器人、非法路径一律 404，不是故障。
- `GET /api/v1/<bot-slug>/inbox?since=<message_id>&limit=<1..200>`：拉新
  消息，时间升序，默认 50 条；`since` 传上次处理到的 id（不含该条）。
- `GET /api/v1/<bot-slug>/inbox/<message_id>`：取单条。
- `POST /api/v1/<bot-slug>/outbox`：发回复，JSON `{"text", "mentions?",
  "reply_to_message_id?", "reply_in_thread?"}`，32KB 上限，30 次/分钟
  （超限 429）；202 即受理。
- `GET /api/v1/<bot-slug>/health`：health 原样。
  `GET /api/v1/<bot-slug>/settings`：`{"bot", "name", "history_allowed"}`，
  每次唤醒先读。

## Muse 侧逻辑

- Watcher：轻量轮询 hook，每 10 秒调 inbox（带 since）；只有新
  @<机器人 B 名> 才完全唤醒；轮询失败不唤醒、下轮重试。注意：60 秒不是
  平台限制——飞书接口没有最小轮询间隔，Muse hook 的最小间隔是 5 秒；
  不要用 cron 搭 watcher（cron 最小粒度 1 分钟，做不到 10 秒），必须用 hook。
- 小任务唤醒后不新建对话：任务在唤醒会话内处理，回复写回群里。大任务
  （新功能、多步骤、需多日跟进）单开一个对话专门做，群里只报进度和结果。
  如需主对话同步，由朋友另行要求。
- 只回 @<机器人 B 名> 的；忽略自己发的（sender_type=app 且 sender.id 为
  该机器人 app_id，可从发出消息的 sender 观测，不向管理员索取配置值）；
  忽略 sender 为空的系统消息；按 message_id 去重，同一条 @ 只回一次。
- 查历史：先读 settings。false 回「未授权查看历史记录」；true 时搜寻群
  历史（可追溯到建群）与自家记忆/过往对话，给出最合适的答复，问起时
  直接复述；涉既往上下文主动先查，不凭空猜。绝不声称能直读对方用户的
  私人对话。
- @ 对方：mentions 填 open_id（不是 app_id）。**open_id 因 app 而异**：
  同一人在不同机器人视角下 open_id 不同，只能用自己 inbox 里实测到的
  ID，绝不能用另一个机器人记录里的 ID。ID 只用实测到的，绝不猜。
- 守卫（由朋友定，推荐口径）：群里 @ 默认直接执行（改配置、改文件、
  部署、重启等），做完群里报结果；只有删数据且无法恢复、花钱、分享密钥、
  动他人账号或机器四类，群里只回需确认的 ack、回主对话确认后才做。
- 每次唤醒先查自家额度，到朋友定的红线则静默退出。
- 密钥红线：App Secret 绝不进群聊、绝不进任何 Muse 聊天；绝不索取、
  接收、复制、记录 App ID/Secret——配置已由管理员填好，只用 API 令牌。

## 已实测（联调不用重猜）

@ 用 open_id；用户 sender 为 open_id，机器人 sender 为 app_id；mentions
恒在（系统消息为空数组）；回复的 parent/root 指向原 @；中转防自回环与
去重已验证；list-chats 最小权限 `im:chat:readonly`；机器人间互相 @ 正常
进入对方轮询历史、mentions 完整。

## 验收

1. 凭令牌调 health，token_ok 为 true。2. 以机器人身份发一条测试消息，
   群里可见。3. 用户 @机器人，正确回复，无重复、无自回环。
4. 对方机器人 @本机器人应答、本机器人 @对方机器人应答（两边在场）。
5. 全过后长期运行。
